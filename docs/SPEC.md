# CRM тикетов в Telegram — техническое задание (v0.1)

## 1. Суть
Telegram-бот живёт в нескольких рабочих чатах (например «Показания счетчиков», «Разработка», «Эксплуатация»).
Любой участник чата пишет `@бот` + текст (с файлами или без) — создаётся тикет.
Карточка тикета уходит в служебный чат поддержки (CRM-чат), где с ним работают операторы.
Параллельно есть веб-панель для тех же действий.

Нагрузка: 2–10 тикетов в месяц, операторы — владелец и пара пользователей.

## 2. Роли
- **Автор** — любой участник рабочего чата, тегнувший бота.
- **Оператор** — пользователь из белого списка (Telegram ID), работает в CRM-чате и веб-панели.
- **Админ** — оператор + управление чатами, категориями, шаблонами, операторами.

## 3. Создание тикета
1. Сообщение в рабочем чате с упоминанием бота → новый тикет `#N`.
2. Категория = рабочий чат, откуда пришло сообщение (сопоставление чат → категория хранится в БД).
3. Сохраняются текст, вложения (фото, документы, видео, голосовые), автор, chat_id, message_id.
4. Бот отвечает автору реплаем: «Создан тикет #N».
5. В CRM-чат уходит карточка:
   ```
   Новое сообщение в тикете #N
   Категория: … · Приоритет: … · Статус: Новый
   Автор: …
   "текст сообщения"
   [Взять в работу] [Отложить] [Закрыть]
   ```
   Вложения пересылаются следом (или группой).

## 4. Привязка сообщений к тикету
- Реплай автора (или любого участника) на сообщение, относящееся к тикету (исходное, ответ бота, публичный ответ оператора) → добавляется в этот тикет, в CRM-чат приходит «Новое сообщение в тикете #N».
- Сообщение с тегом бота вне ветки тикета → новый тикет.
- Для этого храним таблицу `message_links (chat_id, message_id → ticket_id)`.

## 5. Статусы
`Новый` → `В работе` → `Отложен` ↔ `В работе` → `Закрыт`.
- Новое сообщение от автора в закрытом тикете → тот же тикет переоткрывается в `В работе`, сообщение добавляется в его ленту.
- Кнопки на карточке: «Взять в работу» (назначает нажавшего оператора), «Отложить», «Закрыть».
- Карточка обновляется (edit) при смене статуса, вместо спама новыми сообщениями.

## 6. Приоритеты
Низкий / Обычный (по умолчанию) / Высокий / Срочный. Меняется в веб-панели (и командой в CRM-чате).

## 7. Ответы операторов
- По умолчанию ответ — **внутренний комментарий** (виден только операторам).
- Если отмечен флажок «Видно клиенту» — ответ уходит в исходный рабочий чат реплаем на сообщение автора.
- В Telegram: оператор отвечает реплаем на карточку в CRM-чате → внутренний комментарий. Под комментарием бот показывает кнопку «Отправить клиенту» — нажатие публикует этот ответ в исходный рабочий чат.
- В веб-панели: поле ответа + чекбокс «Видно клиенту».
- Шаблоны быстрых ответов (хранятся в БД) — выбор в веб-панели и командой `/t <имя>` в Telegram.

## 8. Почта
- Отдельный Gmail-ящик.
- Из тикета можно отправить письмо стороннему получателю по шаблону (шаблоны в БД, с подстановками: `{ticket_id}`, `{text}`, `{author}` и т.д.).
- В тему письма добавляется метка `[#N]`; ответы на письмо (по теме и заголовкам `In-Reply-To/References`) возвращаются в тикет и приходят в CRM-чат.
- Транспорт выбирается автоматически: пароль приложения Gmail → приём IMAP, отправка SMTP (или SMTP-relay на любом порту); иначе Gmail API по HTTPS с OAuth (refresh token, scope gmail.modify). Опрос непрочитанных во «Входящих» раз в 1–2 минуты. На DigitalOcean исходящий SMTP закрыт — отправка по SMTP завершается понятной ошибкой, приём по IMAP работает.

## 9. Веб-панель (Telegram Mini App)
- Открывается внутри Telegram кнопкой бота (menu button / inline-кнопка «Открыть CRM»).
- Авторизация через Telegram WebApp `initData` (проверка подписи HMAC по токену бота), доступ только операторам из белого списка.
- HTTPS-адрес без покупки домена: `<IP дроплета>.sslip.io`, сертификат Let's Encrypt через Caddy.
- Список тикетов с фильтрами: статус, категория, приоритет.
- Карточка тикета: лента сообщений, комментарии, вложения, смена статуса/приоритета, ответ с чекбоксом «Видно клиенту», отправка письма по шаблону.
- Справочники: чаты/категории, шаблоны ответов, шаблоны писем, операторы.
- Статистика не нужна.

## 10. Стек и деплой
- Python 3.12, aiogram 3, FastAPI (Mini App, Jinja2 + HTMX + telegram-web-app.js), SQLAlchemy 2 + Alembic, PostgreSQL.
- Docker Compose: `bot`, `web`, `mail-worker`, `db`, `caddy` (HTTPS для `<IP>.sslip.io`).
- Дроплет DigitalOcean.
- Секреты (`BOT_TOKEN`, `GMAIL_USER`, `GMAIL_APP_PASSWORD`, `SMTP_PASSWORD`, `GMAIL_CLIENT_ID`, `GMAIL_CLIENT_SECRET`, `GMAIL_REFRESH_TOKEN`, `DATABASE_URL` и т.д.) только в `.env`, `.env` в `.gitignore`, в репо — `.env.example`.

## 11. Модель данных (черновик)
- `chats` (id, tg_chat_id, title, category_id, is_support_chat)
- `categories` (id, name)
- `users` (id, tg_id, name, role)
- `tickets` (id, number, status, priority, category_id, author_id, assignee_id, source_chat_id, source_message_id, card_message_id, created_at, updated_at)
- `messages` (id, ticket_id, kind[author|internal|public|email_in|email_out], author_id, text, created_at)
- `attachments` (id, message_id, tg_file_id, file_name, mime)
- `message_links` (chat_id, message_id, ticket_id)
- `reply_templates` (id, name, text)
- `email_templates` (id, name, subject, body)
- `emails` (id, ticket_id, direction, message_id_header, to, subject, body)
